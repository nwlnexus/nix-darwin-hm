# Server hosts (d.server)

> Read on demand; moved out of the always-loaded `AGENTS.md` / `CLAUDE.md` (olympus-sdk#840). Headless Mac servers.

## Server hosts (d.server)

`d.server.enable = true` in a nix-darwin host (`system/darwin/server.nix`, which turns on `home/server.nix` for the primary user) makes a Mac a headless server (olympus-sdk #694, H20). mmini-01 uses it, and data-hub will. Off by default, so the other Macs are unchanged (`just check-darwin`). When on:

- **No GUI.** `gui-small`, `gui-full`, `business` and `gaming` are asserted off; `base` and `dev` stay. The always-on `iterm2` (and its `duti`) and `obsidian` casks are dropped, and the 1Password app integration is off (`d.apps.onepassword.gui` defaults to `false`).
- **Tailscale** is the Homebrew formula (`d.profiles.base.tailscale = "formula"`, asserted), run by a LaunchDaemon this module declares (unless `d.server.tailscaleDaemon = false`, for a host where something else already runs tailscaled as a system daemon: data-hub, Ansible's tailscale role), `com.tailscale.tailscaled` (`launchd.daemons.tailscaled`, running `/opt/homebrew/bin/tailscaled`), so it starts at boot with nobody logged in. It is not the `tailscale-app` cask and not `sudo brew services start tailscale`; run only one of them, because two `tailscaled` cannot share the socket. Join the tailnet with `sudo /opt/homebrew/bin/tailscale up --ssh --advertise-tags=tag:mac-server` (sudo's PATH has no Homebrew).
- **Power:** `power.sleep.{computer,display,harddisk} = "never"` (computer asserted), `power.restartAfterPowerFailure` and `restartAfterFreeze`, `networking.wakeOnLan.enable`. nix-darwin applies those with `systemsetup`, which does nothing without Full Disk Access, so a `postActivation` step also runs `pmset -a sleep 0 displaysleep 0 disksleep 0 autorestart 1 womp 1`.
- **Remote Login** (sshd) is brought up at boot by `launchctl enable system/com.openssh.sshd` and `launchctl bootstrap` when it is not loaded (not `systemsetup -setremotelogin`, which needs Full Disk Access). The first time on a fresh Mac, the owner turns it on in System Settings so they can ssh in at all.
- **Passwordless sudo for the primary user only** (`security.sudo.extraConfig`, `/etc/sudoers.d/10-nix-darwin-extra-config`); Touch ID for sudo is off. Runner jobs run as a separate unprivileged user and never get it.
- **Nothing personal:** no memory-gateway client, no agent-host layer (its Remote Control services are LaunchAgents, so a GUI session; asserted off, which also rules out the second-brain), no autoMode or telemetry source, no auto-login (asserted unset), and the private `olympus-sdk` input is neither fetched nor linked, so a fresh Mac with no ssh key builds.
- **Every service the role adds is a LaunchDaemon.** The dev profile's own `cargo-sweep` LaunchAgent is unchanged and only runs while the user is logged in.
- **Not managed by nix:** Screen Sharing, and FileVault (the minis keep it off so they reboot unattended after a power cut).
- **`d.server.ciRunner`** (`system/darwin/server-ci-runner.nix`, `scripts/server/ci-runner-loop.sh`): a native ephemeral just-in-time GitHub Actions runner, one job at a time, as the hidden unprivileged `_ghrunner`. A root LaunchDaemon mints an installation token from the GitHub App files in `/var/root/ci-runner/` (root-only, paths are options), asks for a JIT config and passes it to the runner in its environment, then wipes the runner user's home and work dir. Pinned official `actions/runner` release via `fetchzip`. Asserted to need `d.server.enable`. Hardening (olympus-sdk #394): between jobs the loop boots out the user's `user/` and `gui/` launchd domains, kills and checks its processes, removes its crontab and at jobs, empties its home including `~/Library` (only the TCC-protected container folders and file-free folders macOS recreates or pins with `sunlnk`, such as `~/Library/Preferences` and `T/com.apple.trustd`, may stay), its `DARWIN_USER_DIR`/`_CACHE_DIR`/`_TEMP_DIR` and its files in `/private/tmp`, `/private/var/tmp` and `/Users/Shared`, and checks that no non-Apple launchd service survived; activation puts the user in `/usr/lib/cron/cron.deny` and `at.deny` (a deny entry, not a `cron.allow` that would lock out other accounts) and drops any direct Public-folder share group membership, and creates `/var/log/ci-runner.log` root 0600. `networkIsolation` (default on; `enable = false` per host flushes it) renders pf rules into a child anchor of Apple's `com.apple` anchor point (`com.apple/400.olympus-ci-runner`; `/etc/pf.conf` is untouched) that the loop loads, enables pf with `pfctl -E` and verifies before every registration: for `_ghrunner` only, DNS to the `<ci_dns>` table (`dnsResolvers` plus the IPv4 nameservers of `/etc/resolv.conf`, added by the loop) passes, loopback below port 49152, the RFC 1918, CGNAT/tailnet, link-local and multicast IPv4 ranges, the site's own global IPv6 prefixes (`<ci_lan6>`: the /56 around each global address of the host, refilled by the loop every iteration; an unparsable address blocks all IPv6) and ULA/link-local/multicast IPv6 are blocked (`block return`), public IPv6 stays open (the 1Password Connect host answers on IPv6; `blockIPv6 = true` blocks all IPv6 but `::1`); `allowedDestinations` adds narrow TCP exceptions. Both the wipe and the pf check fail closed: the loop backs off and registers no runner. `group`/`labels` are per host: a release-only Mac registers in its own restricted group with its own label (F1b). Health (olympus-sdk #392): the loop records `last_wipe_ok`/`last_wipe_timestamp` after every wipe and `last_registration_timestamp` after every JIT registration in `stateFile` (`/var/db/ci-runner/state`, root-only, outside `workDir`); `heartbeat` (default on) adds the root LaunchDaemon `io.olympus.ci-runner-heartbeat` (`scripts/server/ci-runner-heartbeat.sh`, `StartInterval` 60 s) that pushes the gauges `ci_runner_daemon_up`, `ci_runner_runner_up` (a `Runner.Listener` of the runner user is running), `ci_runner_last_registration_timestamp_seconds` and `ci_runner_last_wipe_ok` with resource attributes `service.name=ci-runner` and `host.name=<LocalHostName>` over OTLP/HTTP JSON with curl to `heartbeat.endpoint` (default: the cluster collector's tailnet name, port 4318). In Prometheus they arrive as `{job="ci-runner", host_name="<host>"}`; the cluster alert rules are olympus-gitops group `ci-runners-macos`. Failed pushes only are logged to `/var/log/ci-runner-heartbeat.log` (root 0600, newsyslog).
- **`d.server.linuxVm`** (`system/darwin/server-linux-vm.nix`, `scripts/server/vm-run.sh`, `scripts/server/vm-provision.sh`): a Tart Linux arm64 VM (k3s agent) as a headless LaunchDaemon on a bridged NIC, run as the primary user. Tart comes from nixpkgs (`pkgs.tart`; the `cirruslabs/cli` Homebrew tap no longer loads on current Homebrew). `server-vm-provision` (not run by a switch) creates and hardens the VM on Tart's NAT network before the daemon ever starts it. Asserted to need `d.server.enable`.
